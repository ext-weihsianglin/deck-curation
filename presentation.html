04 / What we are building

Train the scorer. Use it to guide a rewrite.

P1 estimates sampled top-group membership. The report exposes score changes and guardrail findings—not proven citation uplift.05

Two flows: learn the scorer, then use it in the harness

Offline: labeled HTML/query records go through DOM parsing and Markdownify serialization, embeddings, and context feature computation. The prepared corpus includes textual vector shards. Train/validation/test partitions are host-disjoint. LR transformations are fitted on training data; validation guides development and test remains held out. The checkpoint bundles model weights and transformation/schema metadata. Feature explanations are computed at scoring time using the actual transformed inputs.

Demo app: a host page and query group use the same preprocessing and feature contract. Query/document embeddings come from cache or the enabled OpenAI API. P1 provides an initial analysis report with per-query scores and feature effects. The LLM receives the rewrite prompt, parsed document/chunks, queries and original P1 feedback. Proposed edits undergo edit-contract and language validation; valid drafts are rescored and checked for factual fidelity. The final report exposes before/after P1, feature effects, content diffs and findings. Evaluation is grouped visually for clarity; this is not a claim that every check runs simultaneously or after scoring.

The harness keeps the host, queries and scorer fixed while editing permitted content. In LR, unchanged transformed-feature contributions cancel in log odds: Δlogit(P1) = Σ w_j Δz_j. This is a controlled model comparison, not proof that latent host associations disappear or that citation rates improve. Prompt optimization is intentionally introduced later, not on this architecture overview.

What we engineered and how to read it

The 55-input contract is verified against the v7.1 artifact manifest and markdownify_context.py. These are presentation groupings, not separately trained models. Size and structure combines nine log-count features with four structure features. Composition contributes fourteen features. The remaining context groups are four prompt features, five URL features, four metadata features and five extraction-quality features: 45 context inputs total.

The ten semantic features are query similarity to title, H1, outline, page and URL path, plus section maximum, top-three mean, median, lower quartile and upper quartile. These are cosine similarities computed in the original 3,072D embedding space; the LR does not receive every embedding dimension as a separate feature. Earlier lexical coverage features are not part of this served semantic contract.

Query and URL features are fixed during a permitted page rewrite. Document features may change, but editable features are still bounded by the source and edit contract. Source metadata is not an invitation to manufacture schema or modify protected inputs.

The right-hand bar chart faithfully redraws the eight semantic-similarity coefficients printed on page 3 of the user-selected Downloads/lr-weight-scores.pdf. The full weight section spans pages 3–6 and is linked unchanged. This is a selected semantic group, not a global importance ranking; fixed title/path weights and other families remain in the complete report/artifact. Coefficient magnitude alone does not establish editing leverage or causality. The chart uses a shared linear scale and preserves coefficient signs.

Structure, not the full prompt

The supplied system message combines a promoted 14-step editorial procedure with the fixed security, source, output and language-preservation contract. Evolutionary analogy without extra jargon

A reflection model reads evaluated rewrites, their source evidence, query scores and fidelity findings. It proposes one reusable child procedure. Parent and child are compared on the same reflection pages; strict improvement advances to the full selection set.

The Pareto frontier can preserve page specialists alongside a prompt with a higher overall mean. Every candidate rewrites the original pages. It does not mutate the prior generated content. The implementation uses one child per round and disables crossover.

Reward semantics and illustrative judge response

The displayed JSON is authored for explanation using the actual GPT-5 response schema; it is not a recorded response. Illustrative b000041 changes “often six bed facilities” to “up to six beds,” inventing an upper bound. Illustrative b000087 changes “extended hours” to “evening support,” which the available source cannot establish. IDs and findings are illustrative. In real responses, source_ids must reference known blocks in the original chunk.

Unsupported and uncertain are fidelity-checker verdicts. Unsupported claims, changed facts, dropped material qualifiers and important omissions receive the unsupported penalty. Uncertain means sufficient support cannot be established. Supported edits incur no fidelity penalty.

Count affected edited blocks, not individual factual issues. Three unsupported claims in one block incur one 0.05 deduction. If both unsupported and uncertain concerns apply, use only the stronger unsupported deduction. The policy does not distinguish number or severity of issues within a block, and does not divide by edit count. The research reward also incorporates rewriter self-reported unsupported additions or missing evidence when these require a stronger verdict.

Raw P1 is the mean over distinct queries for a page. Candidate selection averages page rewards on the fixed 30-page set. Abstention retains original P1 with no factual deduction. Technical failures have separate accounting. Replacing absolute P1 with ΔP1 against the same fixed original pages does not change mean-reward rankings. The completed run had 703 attempts and 13 technical failures, stopping at the proposal limit; penalty weights remain exploratory.

Next steps

Test what actually improves the page

About 97% of the reward gain came from fewer fidelity penalties, not higher P1.
Compare four versions of the same pages to understand why.

1. Leave the page unchanged

  • Keep the original words and layout.
  • Use its score as the starting point.

2. Change only the wording

  • Make existing answers clearer; add no new facts.
  • Keep the headings, lists and layout the same.

3. Change only the structure

  • Keep the words; change permitted formatting.
  • Check whether P1 rises without a better answer.

4. Change both

  • Combine clearer wording with better structure.
  • Check whether the combination helps more.

For each version: compare P1 and factual errors. Ask reviewers which answer is more useful, without telling them how it was made.

Proposed experiment, not a completed result. Keep “no useful supported edit” as an acceptable outcome.18

Next experiment in plain language

Use the same pages and queries for four controlled versions: unchanged, wording only, structure only, and both. Reviewers should not know which condition produced an answer. Compare raw P1, feature contributions, factual errors, safe-edit rate and usefulness separately. Structural edits require an explicitly permitted experimental configuration; do not imply the present fixed edit contract allows arbitrary restructuring.

Reward improvement was 0.0227368094: 0.022 from lower penalties and 0.0007368094 from higher raw P1. Lower penalties account for about 96.76%. This suggests a conservative outcome but does not prove the penalty weights caused it. Audit judge findings and test penalty settings; limited scorer sensitivity and the available safe edits are alternative explanations. Do not force changes merely to avoid abstention.
